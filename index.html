Project overview

A focused toolkit for surveillance media research.

CCTV recorders do not always store footage as ordinary video files. Depending on the recorder and disk layout, useful data may require format-aware parsing, stream carving, and careful examination of the storage source.

Why a specialized workflow?

Video recovery is not always a file-system problem.

  • Recorder-specific storage: surveillance systems may use proprietary layouts or stream containers.
  • Fragmented data: deleted or interrupted recordings may need careful investigation rather than a simple copy operation.
  • Multiple channels: separate camera streams can be interleaved or stored in device-specific structures.
  • Documentation matters: successful recovery depends on the source media, device, format, and actual implemented support.

What OmniDVR aims to provide

One project to explore recovery-oriented tooling.

  • Storage-level access: a workflow designed to examine physical media where supported and authorized.
  • Format-aware engines: code organized around several DVR-family and generic stream approaches.
  • Stream export: workflows for saving recovered data in stream-oriented formats.
  • Inspectable source code: an open repository for researchers, developers, and technically minded investigators.

Compatibility note: vendor names and formats below describe the project's documented targets, not a guarantee that every model, firmware revision, disk layout, or recording will be recoverable. Check the repository and test on known sample media before relying on a specific workflow.

Core capabilities

Built for the details behind the video.

The codebase separates disk access, format-specific processing, stream export, and preview-related helpers into distinct components.

01 / Storage

Physical drive workflow

The project documents low-level Windows disk access for examining source media at sector level where permissions and supported hardware allow it.

02 / Format engines

Vendor-oriented parsing

Separate engine modules organize format-specific processing for documented Dahua-family and Hikvision-family targets.

03 / Stream carving

Generic H.264 / H.265 paths

The repository describes generic NAL-based carving approaches for compatible raw surveillance stream data.

04 / Export

Stream-oriented output

Documented export paths include direct stream-oriented outputs such as DAV, HIK, or H.264 where the relevant engine supports them.

05 / Investigation

Timeline-oriented review

Explore recovered stream data with attention to sequence, timestamps, source context, and what can or cannot be established from the media.

06 / Integrity

Evidence-conscious handling

The project documents read-oriented source access and hash logging. Forensic use still requires a validated procedure and independent integrity checks.

A transparent workflow

From source media to reviewable output.

A typical investigation has several separate stages. The exact controls and results depend on the current app build and the source device.

Prepare the source

Identify the drive, document its origin, and work only with media you own or are authorized to examine.

Inspect and scan

Select the appropriate workflow, format family, and source options supported by the installed version.

Review stream data

Examine discovered data, channel associations, timestamps, and any available preview information with care.

Export and verify

Save supported outputs, record the steps taken, and independently verify hashes and results when evidence matters.

Forensic caution: do not use the original evidence drive for routine experimentation. Prefer a verified image or controlled test media, follow your organization’s procedures, and document any acquisition, access, and export activity. A software feature description is not a substitute for validation.

Format families

Approaches for different recording ecosystems.

The project documentation identifies several format families and generic stream approaches. Real-world compatibility should always be confirmed against actual devices and sample recordings.

Documented vendor targets

Implementation-dependent format handling

  • Dahua-family: documented targets include DHFS-related variants and DHAV-oriented stream handling.
  • Hikvision-family: documented targets include HikFS / HIKM-related paths and MPEG program streams.
  • Other DVR / NVR sources: generic carving may be relevant when compatible H.264 / H.265 elementary stream data is present.

Stream and output concepts

Raw video data is not always a complete playable file

  • H.264 / AVC: common video elementary-stream format that may appear in compatible raw data.
  • H.265 / HEVC: a newer codec family that may require a compatible player or decoder.
  • Container vs. stream: a raw stream may lack audio, timing metadata, or container structures expected by ordinary players.
  • Output extensions: the extension alone does not prove a file is complete, authentic, or compatible with every player.

Evidence handling

Recovery results deserve careful verification.

A recovered video can be incomplete, fragmented, missing metadata, or reconstructed incorrectly. Good practice means documenting uncertainty rather than presenting every result as conclusive.

Preserve the source

Use a controlled acquisition or verified disk image whenever possible. Minimize unnecessary access to the original device.

Document the procedure

Record the source identifier, software version, settings, date, output paths, warnings, and any manual actions taken.

Verify the output

Use independently computed cryptographic hashes where appropriate, keep original outputs unchanged, and note verification limits.

OmniDVR Forensic Suite is a technical tool, not a guarantee of admissibility, completeness, or suitability for a particular legal process. Follow applicable laws, professional standards, and case-specific procedures.

Frequently asked questions

Before you start a recovery.

Answers to common questions about setup, source media, compatibility, and responsible testing.

Is OmniDVR Forensic Suite free and open source?

The repository identifies the project as open source and includes an MIT license. Read the current license file in the repository for the exact terms that apply to the code.

Which operating system is supported?

The current project documentation targets 64-bit Windows 10 and Windows 11. Other operating systems are not promised by this page; check the repository for the latest support information.

Can it recover video from every DVR or NVR?

No recovery tool can guarantee universal support. Device family, firmware, recording format, disk layout, fragmentation, overwriting, and the condition of the media can all affect results. Treat vendor and codec lists as targets, then verify support with controlled sample media.

Do I need administrator privileges?

Some physical-drive operations on Windows require elevated permissions. Only grant them when necessary, make sure you understand which device is being accessed, and follow your own security policy.

Why does an exported stream not open in my video player?

A raw elementary stream may not include a conventional container, audio track, timestamps, or index. The relevant codec and player support also matter. Check the exported format and repository documentation before assuming the data is invalid.

Does the site include real application screenshots?

Not yet. The gallery contains explicitly marked placeholders. Replace them with genuine screenshots from the current build before publishing claims about the interface or results.

How can I report a bug or propose an improvement?

Visit the repository’s Issues section. Include your operating system, Python version, the exact command or workflow, a sanitized log, and steps to reproduce the issue. Do not upload private recordings or sensitive forensic evidence.

Can OmniDVR be used for an official forensic case?

Suitability depends on validation, procedure, the investigation, and applicable requirements. Test independently, document all actions, preserve source media, verify outputs, and consult a qualified practitioner where required. This page does not certify the tool for legal use.
